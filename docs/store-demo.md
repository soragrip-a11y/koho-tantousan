# 店舗案内デモ

公開先: https://local-koho.com/demo/stores/ （既存 GitHub Pages、`dist/demo/stores/` の独立追加）

入口 `#line` → 店舗一覧 `#shops` → 店舗 A `#store`。`#manage` は認証のない操作体験で、管理画面の本番公開を意味しません。店名・お知らせは架空です。全画面にデモ表示、HTML に `noindex,nofollow,noarchive` を設定し、sitemap や既存本番ページには追加しません。

## 使える操作

写真（JPEG/PNG/WebP、2MB以下、最大960pxへ縮小）、40文字の見出し、180文字の本文、終了日時を入力できます。お知らせごとに編集、売り切れ、終了、非公開、再掲載を操作できます。編集は現在の状態を維持し、再掲載は明示操作です。期限は端末時刻で判定し、お客さま表示は日本時間です。開いたままでも1秒以内に終了表示に更新します。在庫保証はありません。

保存はこのブラウザの localStorage の専用キーのみ。共有DBやサーバーへのアップロードはありません。リセットでこのデモだけを初期化します。保存不可・容量不足はエラーとして案内します。

## 構造と本番の最小条件

- `model.js`: 検証・状態判定・LocalRepository。実バックエンド用 Repository に差し替える境界。
- `app.js`: 表示、ルーティング、写真縮小。文字列はエスケープし、画像は許可した raster data URL のみ表示。
- 本番には店舗管理者の正規認証とサーバー側の店舗ごとのアクセス制御が必須。店舗IDをブラウザから受け取るだけの方式は禁止。認証された所属から書き込み対象を決定する。
- 共有DB（店舗、お知らせ、終了日時、公開状態）、画像保存（容量・形式制限・削除）、サーバー時刻での期限判定、監査記録とバックアップ、運用責任者と実店舗の掲載許可が必要。
- お客さまはログイン不要。公開読み取りAPIは公開店舗の公開お知らせだけを返す。非公開情報を配信して画面で隠す方式にしない。
- 既存 repo に流用できる店舗向け認証・DB・画像保存基盤は見つかっていない。ドメイン変更だけでは本番化できない。新規アカウント・課金・秘密情報・権限追加は行っていない。

## 検証

`npm ci && npm test`（既存含め94件）。ブラウザ検証は一時的に Playwright を入れ、`node scripts/test-store-demo-browser.mjs`（WindowsのEdgeを使用）。Playwrightは本番依存にもlockfileにも追加しない。

320 / 390 / 430 / 1280px で全4画面の横はみ出しなしを検証し、390pxの最初の画面に店名・主要情報・期限が入ることを確認。空欄、長文、写真入力と保存・再読込、壊れた画像、容量超過、個別の売り切れ・終了・非公開、編集状態維持、過去期限と開いたままの期限到達、再クリック、戻る、リセット・再読込、JavaScript例外なしを検証。

スクリーンショットと結果はローカル `tmp/store-demo/`（非コミット）。既存デプロイCIは `npm ci` → `npm run sync:blog` → `npm test` → `dist` を GitHub Pages に配信する。
