## 「行ったよ」の動きと順位案

- 公開デモで押せるのは自己申告ボタン。店舗ごとにこのブラウザー内で1日1回、日本時間0時を境界とする。
- 直近7日は今日を含む7暦日。同日の再クリックは追加しない。同一originの対応ブラウザーでは Web Locks で複数タブの更新を直列化する。
- 実人数・来店証明・全利用者集計ではない。別ブラウザー、保存削除、端末時計変更などを防ぐ本番不正対策ではないことを画面に明記。
- 順位案は「行ったよ」の7日間合計だけを使う。投稿回数は使わない。同数は同順位、順序は既存順維持。オーナーが週1回確認し、メニューは手動編成する。自動並べ替え・自動通知はない。
- 公開画面に管理履歴、投稿・編集回数、オーナー用順位表は含めない。公開サイトのデータは販売情報を含まないサンプルと本人のブラウザー内自己申告だけ。

## 管理操作と履歴の分離

以前の公開デモから管理エディターを除去した。旧 #manage は入口に戻り、管理UIを表示しない。旧ブラウザー専用デモ保存キーは読み出さず削除する。

管理プレビューはリポジトリ外のローカル owner-preview ディレクトリにのみ作成。GitHubにも dist にも含めない。架空データによる新規投稿、編集、売切れ、終了、非公開、再掲載、写真入力と各操作の別記録、直近7日の集計・順位を試せる。ループバックのみで配信し、架空の履歴をこのローカルoriginのブラウザー内に保存する。実データ入力・実運用は禁止。

公開JavaScriptに管理データを埋め込んで隠す方式ではない。認証未整備のため、実データの管理画面は公開していない。ローカルプレビューは公開デモの「行ったよ」とも接続されず、全件が架空。

## 本番に不足する最小条件

正規認証、店舗所属に基づくサーバー側の権限分離、共有DB、画像保存、サーバー時刻での期限・日次判定、来店自己申告の重複・濫用対策が必要。管理履歴と集計・順位は認証された管理者の専用APIだけに返す。公開APIには公開済みお知らせのみを返し、履歴・非公開情報を混ぜない。

現時点では、管理者が外出先から実店舗の新規投稿数・編集数・売切れ操作・行ったよ数・順位を共有データとして確認する機能は未実装。ドメイン変更だけでは本番化できない。新規APIキー、OAuth連携、契約、課金、LINEログイン権限付与は行っていない。

## 構造と検証

model.js は公開サンプル、日付判定、本人ブラウザーの自己申告を扱う純粋関数。app.js は表示と公開デモ用保存。管理プレビューのデータ・コードは配信物に含まない。

npm test: 既存を含む95テスト。日付境界、7日集計、再クリック、複数店舗、公開bundleへの管理機能混入防止を追加。
任意の実ブラウザー検証: 一時的に Playwright を入れ node scripts/test-store-demo-browser.mjs を実行。320 / 390 / 430 / 1280px、1タップ直通、戻る、再読込、連打、同時タブ、日本時間0時、保存破損、旧管理URL・旧データの非表示と削除、非公開エンドポイント不在を確認。
画像も同スクリプトでコードからPNG化。スクリーンショットは tmp/store-demo-v2/（非コミット）。
ローカル管理プレビューは別途3件のモデルテストと実ブラウザーで新規・編集・売切れの区別、非公開操作、架空順位、写真保存・再読込、スマホ表示を確認。
