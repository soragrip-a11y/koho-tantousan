# 中富店デモ：お客さん用と店員さん用の入口を分離

お客さん用URL: https://local-koho.com/demo/stores/
店員さん実演用URL: https://local-koho.com/demo/stores/staff.html
店員さん専用の見え方確認: https://local-koho.com/demo/stores/staff.html#preview

## 今日の実演
1. 同じスマホ・同じブラウザーで店員さん実演用URLを開く。
2. 写真を撮る／選ぶ／写真なし → ひとこと → 確認して載せる。
3. 店員さん専用の見え方確認へ移動する。書き直し・売り切れ・取り下げはここだけで操作する。
4. お客さん用URLを別タブで開くと、同じブラウザー内の内容を閲覧できる。操作ボタンは「行ったよ」のみ。
5. 最後は店員さん用ページ下部の「練習を最初からやり直す」でリセット。

Safari/Chrome/LINE内ブラウザーを切り替えると保存を共有しない。別のスマホや別人へ投稿・送信しない。架空の内容だけで実演する。

## 分離の境界
お客さん用は index.html + customer.js。撮影・選択・投稿・編集・取り下げ・リセット・店員入口のリンクやボタンはない。操作は閲覧と簡易「行ったよ」だけ。初期URL、旧 #post / #line / #store/nakatomi、無効hash、戻る・進む・再読込のすべてで同じ閲覧画面になる。店員向け app.js / post-ui.js は読み込まない。

店員さん用は staff.html + app.js + post-ui.js。店員向け見え方確認は staff.html#preview のままで、お客さん用ページへ管理リンクを混ぜない。お客さん用ページから店員ページへの導線はゼロ。以前の #post はもう投稿画面ではない。

これはURLによる秘密保護や本番認証ではない。staff.html 自体は誰でもアクセスできる架空の投稿体験であり、ログイン済みを偽装しない。扱うのはそのブラウザーで作った架空の写真・文章だけ。実際の管理履歴、利用者データ、認証情報は配信しない。操作履歴を作らず、以前のローカル管理プレビューはリポジトリ外のまま公開しない。

## 店員さんの使いやすさ
写真→ひとこと→確認の3段階。大きな文字と主要80px級ボタン。写真は任意。カメラ／画像選択を分け、戻る時は入力を保持。取消・売り切れ・取り下げには確認が入る。連打しても重複投稿しない。日時や集計・順位は入力主画面に置かず、24時間で終了。書き直して載せると24時間に更新。

JPEG/PNG/WebP・10MB以下を最大960pxへ縮小。実機カメラ撮影は端末・ブラウザー対応に依存。カメラ用inputにcapture=environmentを設定。写真選択・縮小・保存・再読込は実ブラウザーで検証。

## 本番に不足するもの
正規認証、店舗別サーバー権限、共有DB、画像保存、サーバー時刻での期限判定、全利用者を対象とする自己申告集計は未実装。ドメイン変更だけでは本番運用できない。OAuth・APIキー・契約・課金は追加していない。
CSP connect-src none / form-action none、noindex/nofollow/noarchive を両ページに設定。既存本番ページ・フォーム・sitemapは変更しない。
