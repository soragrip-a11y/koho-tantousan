# 契約書PDF作成機能

入口: `dist/contract.html`。料金、利用条件、お問い合わせ、書類案内の各ページに入口を追加。
旧 `simulator.html` は料金ページへの移動を維持。

## 操作

1. 契約者・代表者・住所・メールと請求書宛名を入力。
2. プラン、契約日、開始日、初回契約月数（単発は完了日）を指定。
3. 動画の総本数、追加撮影、合意する追加作業を入力。月額の場合、本数と追加撮影回数は毎月分。
4. 交通費・駐車場代・宿泊費ごとに「なし」「確定」「後日精算」を選択。確定額だけを合計に加える。後日精算の上限は空欄なら都度承認、0円なら上限0円。
5. 制作内容・公開先・日程・完成動画の利用範囲、実績掲載の扱いを確認。
6. 受託者の住所を担当者の案内に従って入力。氏名・屋号・メールは公開サイト記載値が初期値。
7. 利用条件を確認して「契約書PDFを作成・保存」。PDFだけでは契約確定にならず、双方の署名・同意記録を別途保存。

iPhoneなど自動保存できない端末は、生成後の「PDFを開く」から共有メニューでファイルに保存する。
フォームを変更すると前のPDFリンクを無効化し、再作成を求める。

## 料金・実費・期間

- 料金は税込。消費税を二重加算しない。
- スタンダード55,000円／月にショート6本、プレミアム150,000円／月にショート8本・ロング2本・4時間撮影1回を含む。
- 超過分はショート8,000円、ロング18,000円。標準本数削減や種類交換は自動計算せず個別相談。
- 追加撮影4時間22,000円、7時間32,000円。プレミアム内撮影の7時間延長は10,000円／月。
- 個別追加作業は「毎月」か「初回期間に1回」。単発はすべて1契約分。
- 確定実費は初回契約全体に対して1回のみ。未確定実費の概算・上限はどの小計にも加算しない。
- 後日精算は発生前の明示承認、対象・上限変更の再承認、実費明細・領収書等、25日締めと支払期限、二重請求防止をPDFに記載。
- 月額の最低期間は1か月／2か月。終了日は開始日を基準に算出し、以後1か月自動更新。初回の更新停止期限（満了14日前）もPDFに反映。
- 確定総額は初回期間の総額で、一括前払請求額ではない。更新後の料金と未確定実費は除外。

## 構成・保守

- `contract-core.js`: 純粋な料金計算、期間計算、入力検証。
- `contract.js`: 入力画面、確認明細、端末内PDF生成と保存リンク。
- `contract-pdf.js`: 日本語の折り返し・改ページ・署名欄。
- `contract-terms.js`: `terms.html` の本文12節のスナップショット。PDF内に全文を収録し、Webページ変更後も署名時の条件を保持する。
- `contract.css`: 既存ブランドを利用した専用レイアウト。740px以下は1列。タップ領域48px以上、入力16px。
- `vendor/` と `assets/fonts/`: バージョン固定のPDFライブラリと日本語フォント。ブラウザで最初に作成ボタンを押したときに同一オリジンから読み込む。

フォーム内容は送信しない。localStorage・cookie等への入力内容保存も行わない。PDFはBlob URLで端末内に作る。
署名済みPDFを後から自動更新する仕組みはない。実際の請求・口座案内・署名回収・保管は従来のLINE／メール運用。

料金変更時は `pricing.html` と `terms.html`、`contract-core.js` を更新し、`npm run sync:terms` を実行。
計算テストの期待値・PDF内の料金条件基準日も確認する。

## 検証・公開

Node.js 22以上とPython 3を使用。公開サイト自体にビルドやサーバーは不要。

```sh
npm ci --ignore-scripts
npm run sync:terms
npm test
```

テストは料金計算・期間・入力検証・DOM連携・生成PDFの構造を確認する。生成例は `tmp/pdfs/` に作成（Git管理対象外）。
PDFはPopplerの `pdftotext` で文字・金額、`pdftoppm` で日本語表示・改ページ・署名欄を確認する。
DOMテストはレイアウトや実ブラウザのダウンロード動作の検証を代替しない。

ブラウザQA用の対応ツールが今回の環境にないため、実機Safari・Chromeでのタップ操作、レイアウト、保存動作は未確認。
手動確認時は、スマートフォン幅、プラン切替、実費の0円と未入力の差、未入力エラー、生成後の修正・再生成、PDF共有／保存、既存問い合わせ・メニューを確認する。

既存の `.github/workflows/pages.yml` はmain更新で `dist/` をGitHub Pagesに公開する。導入は本変更一式をmainへ反映するだけ。サーバー秘密鍵、外部PDF API、顧客データの公開ファイルは不要。
取り消す場合はこの追加コミットをrevertする。既存料金・問い合わせスクリプト・シミュレーターの転送先は変更していない。
